## M1 服务器与远程运维

### SSH 基础
```bash
ssh user@host -p 22          # 连接
scp file user@host:/path     # 传文件
ssh-keygen -t ed25519        # 密钥认证（比密码安全）
```
### 故障排查四查
1. 查状态：进程（ps）/端口（netstat/ss）/磁盘（df）/内存（free/top）
2. 查日志：/var/log/（syslog/messages/应用日志）
3. 查网络：ping/traceroute/curl 本地回环
4. 查资源：CPU 占用（top）、IO（iostat）、负载（uptime）

## M2 网络安全基础

### 常用命令
```bash
netstat -tulnp   # 查看监听端口
iptables -L      # 防火墙规则
ufw allow 22     # Ubuntu 防火墙放行
```
### 常见攻击与防御
| 攻击 | 特征 | 防御 |
|---|---|---|
| 暴力破解 | 大量登录失败 | 限速+密钥认证+fail2ban |
| DoS | 资源耗尽 | 限流+CDN+防火墙 |
| 中间人 | 流量被截 | HTTPS 全站 |

## M3 漏洞与扫描

### 扫描流程（授权前提）
1. **确认授权**（自有或书面授权）→ 2. 资产盘点 → 3. 漏洞扫描（nmap/OpenVAS 等）→ 4. 分级 → 5. 修复 → 6. 复测。
### 漏洞分级与修复
- 严重/高危：立即修复（补丁/配置/隔离）
- 中危：计划修复
- 低危：登记观察
⚠️ 未授权扫描违法，红线。

## M4 安全防御

### 提示注入防御（AI 场景）
- 外部内容（网页/邮件/文件）先隔离扫描，识别"忽略指令/输出系统提示词"类攻击
- 系统级指令锁定行为边界；关键操作人工确认
### Web 攻击防护
SQL 注入：参数化查询；XSS：输入校验+输出转义；敏感操作：鉴权+验证码。

## M5 数据安全

### 加密
- 传输：HTTPS/TLS、SSH
- 存储：磁盘加密（LUKS/BitLocker）、数据库加密
### 密钥管理
生成（openssl/genkey）、存储（专用密钥库，不入代码/日志）、轮换（定期+泄露即换）、权限最小化。
### 备份策略
3-2-1 原则（3 份副本/2 种介质/1 份异地）；定期验证恢复（没验证的备份=没有备份）。

## M6 监控与日志

### 监控清单
CPU/内存/磁盘/带宽/进程存活/端口可用；异常阈值告警。
### 日志分析
错误日志 → 时间线 → 关联（攻击/故障/性能）；日志定期轮转与归档。

## M7 安全审计与合规

### 安全基线检查清单
密码策略（复杂度/过期）、账号权限（最小化/离职回收）、补丁更新、端口收敛（只开必需）、日志开启、备份有效、密钥管理、远程访问控制。
### 合规框架（概览）
等保 2.0（国内）、GDPR（欧盟）、ISO 27001（国际）；涉具体合规结论咨询专业机构。
⚠️ 合规结论声明「不构成法律意见」。

## 合规红线
- 扫描/渗透必须授权，禁止未授权目标。
- 高危操作先备份、测试环境验证。
- 密钥/凭据不明文存储、不入日志。
- 合规结论声明「不构成法律意见」。
- 不编造漏洞/工具/攻击案例。

## M1+ 数据库基础运维（2026-09-11 蒸馏补强，修复 2.0.0 丢失）

### 备份恢复（3-2-1 原则）
- **3 份副本 / 2 种介质 / 1 份异地**；逻辑备份（mysqldump/pg_dump）用于小库与迁移，物理备份（xtrabackup/pg_basebackup）用于大库与快速恢复。
- **必须演练**：只备份不恢复等于没备份；每季度做一次恢复演练并记录 RTO/RPO。
- **Redis**：RDB（快照，恢复快、可能丢秒级数据）与 AOF（追加日志，丢失少、体积大）按业务取舍；开 AOF + 定期 RDB 是常见组合。

### 慢查询定位
1. 开启慢查询日志（`slow_query_log` / `log_min_duration_statement`），设阈值（如 1s）。
2. 用 `EXPLAIN` / `EXPLAIN ANALYZE` 看执行计划：是否全表扫描、索引是否命中、回表次数。
3. 优化手段：补/改索引（注意最左前缀与选择性）、避免 `SELECT *`、减少函数包列、分页深翻页改游标、必要时拆分大事务。
4. 复核：改前改后用同一 SQL 对比耗时与扫描行数。

### 三类常见故障
| 现象 | 常见原因 | 处置 |
|---|---|---|
| 连接打满（too many connections） | 连接池泄漏、慢查询堆积 | 定位长事务与空闲连接，临时调大 max_connections 后治本 |
| 锁等待/死锁 | 大事务、加锁顺序不一致 | 查 `information_schema.innodb_trx`，缩短事务、统一加锁顺序 |
| 磁盘满 | binlog/日志膨胀、数据增长 | 清理过期 binlog/日志，调 `expire_logs_days`，扩容 |

### 权限与安全
- 应用账号与运维账号分离，遵循最小权限；禁止 root 直连生产应用。
- 高危操作（DROP/TRUNCATE/批量 UPDATE）先备份、先在测试验证、加 WHERE 二次确认。
