## 第一部分：安全事件应急响应与溯源

### 1.1 铁律（先记住这三条，其余都是细节）
1. **先保全，后处置**：在删文件、重启、重装之前，先做证据快照。**重启会清空内存中的进程链与网络连接**，这是最常见的取证损失。
2. **不要擅自清理日志**：日志既是指控攻击者的证据，也是判断影响范围的依据。清理日志＝销毁证据，可能引发合规与法律后果。
3. **不隐瞒、不延迟上报**：涉个人信息泄露、关键业务中断、疑似勒索的，按内部制度与法定路径上报。**掩盖的成本远高于披露**。

### 1.2 五步处置流程

| 步骤 | 目标 | 关键动作 | 产出的证据/记录 |
|---|---|---|---|
| **① 遏制** | 止损，阻止扩散 | 隔离受影响主机（**断网而非关机**，保留内存状态）；封禁可疑 IP 与账号；暂停受影响对外服务（评估业务影响后） | 隔离时间点、隔离范围、业务影响清单 |
| **② 取证** | 固定事实 | 内存转储（如条件允许）；`ps -ef` / `netstat` / `ss` 连接快照；登录日志（`last`、`lastb`、`/var/log/secure`）；计划任务与启动项；近期新建/修改文件清单；**记录操作人、时间、命令**（证据链完整性） | 证据快照包 + 操作日志 |
| **③ 根除** | 清除入口与后门 | 定位初始入口并修补；清除持久化项（计划任务/启动项/SSH 密钥/新增账号/WebShell）；轮换所有可能泄露的凭据（**含数据库、云 AK/SK、API Key、SSH 密钥**） | 入口结论、清除清单、凭据轮换记录 |
| **④ 恢复** | 回到可用状态 | 从**可信备份**恢复（确认备份未被污染）；先在隔离环境验证再上线；加强监控观察期（建议 ≥ 2 周） | 恢复验证记录、观察期监控项 |
| **⑤ 复盘** | 不重复踩坑 | 时间线重建（首次入侵 → 发现 → 处置）；根因分析（**问「为什么没能更早发现」，不只问「谁干的」**）；控制措施补齐；责任与流程修订 | 复盘报告 + 整改项与责任人 |

### 1.3 常见入口初判（按发生频次）
| 入口类型 | 典型特征 | 首要核查项 |
|---|---|---|
| **弱口令 / 口令喷洒** | 大量失败登录后突然成功 | `lastb`、`/var/log/secure`、是否有新增高权限账号 |
| **未授权访问** | 开放的管理端口、无鉴权的中间件 | 暴露面扫描、端口清单与防火墙规则 |
| **组件/框架漏洞** | 日志中出现异常请求路径、进程异常拉起 | 组件版本与已知漏洞对照、WebShell 检测 |
| **供应链** | 依赖包/镜像被投毒、更新后异常 | 依赖清单比对、镜像哈希校验 |
| **内鬼 / 凭据泄露** | 无外部入侵痕迹但数据外流、非工作时间访问 | 权限审计、访问日志异常时段分析 |

### 1.4 持久化与横向移动排查点（**记住这一张表**）
- [ ] **计划任务**：`crontab -l`（含各用户）、`/etc/cron.*`、Windows 计划任务
- [ ] **启动项**：`systemd` 服务、`/etc/rc.local`、Windows 注册表 Run 键
- [ ] **账号**：`/etc/passwd` 新增用户、UID 0 的异常账号、Windows 管理员组成员变化
- [ ] **SSH**：`~/.ssh/authorized_keys` 中的陌生公钥
- [ ] **进程**：名称伪装（如 `sshd` 拼写变体）、隐藏进程、异常父进程
- [ ] **网络**：对外异常长连接、DNS 隧道特征、非常用端口出网
- [ ] **Web 目录**：近期新增/修改的可执行脚本（WebShell）
- [ ] **横向证据**：内网扫描记录、Smb/WMI/PsExec 使用痕迹、凭据转储工具残留

### 1.5 上报与沟通
- **内部**：明确单一对外口径负责人，避免多头对外发布互相矛盾的信息。
- **外部**：涉个人信息泄露的，按《个人信息保护法》等相关要求评估报告义务与时限 [待确认：具体报告对象、时限与格式以最新规定及主管部门要求为准]；涉关键信息基础设施的另有专门要求。
- **对客户/用户**：说明「发生了什么、影响谁、已做什么、你该做什么」，不给未证实的结论、不承诺「已完全清除」。

## 第二部分：数据合规与个人信息保护

### 2.1 三原则自查（任何个人信息处理活动都适用）
| 原则 | 自查问法 | 常见不合格表现 |
|---|---|---|
| **合法、正当、必要** | 这项处理有没有明确的目的？不收集这一项能不能达成目的？ | 「先收集了再说」、扩大收集范围 |
| **最小必要** | 字段是否只保留实现目的所必需？保存期限是否明确？ | 全字段收集、无期限保存、离职员工数据长期留存 |
| **告知同意** | 是否以显著方式告知处理目的/方式/种类/保存期限？是否取得同意？ | 隐私政策藏在角落、默认勾选、拒绝即不能用 |

> **其余必须覆盖的环节**：个人信息的**存储与加密**、**访问权限与最小授权**、**委托处理与共享**（须有协议约定）、**跨境传输**、**删除与匿名化**、**安全事件应对**。

### 2.2 数据分类分级（先分级，才谈得上保护）
| 档位 | 判定标准 | 典型措施 |
|---|---|---|
| **公开** | 可对外公开、泄露无影响 | 常规访问控制 |
| **内部** | 仅内部使用，泄露造成轻度影响 | 账号体系 + 访问日志 |
| **敏感** | 含个人信息、商业机密，泄露造成较大影响 | 加密存储、最小授权、操作留痕、脱敏展示 |
| **核心** | 泄露造成严重后果（如大量敏感个人信息、核心算法/源数据） | 强加密 + 严格审批 + 独立审计 + 出境限制 |

### 2.3 数据出境三条路径（**适用情形不同，不能混用**）
| 路径 | 适用情形（概览） | 关键动作 |
|---|---|---|
| **安全评估** | 达到规定量级或属特定情形的出境 | 向主管部门申报评估 |
| **标准合同** | 未达评估门槛的常规出境 | 签订标准合同并向主管部门备案 |
| **保护认证** | 符合认证条件的出境 | 通过专业机构认证 |

> 三条路径的**门槛数值、适用条件与备案流程有明确规定且可能调整**，本项目录不列具体数值，实际适用前**必须核对最新规定与主管部门口径** [待确认]。跨国公司内部传输、境外服务器部署、境外 SaaS 使用均可能构成出境，需先行判定。

### 2.4 技术与组织措施检查单
- [ ] 敏感字段**加密存储**（含数据库字段级加密与密钥独立管理）
- [ ] 展示层**脱敏**（手机号/身份证/银行卡/地址按角色分级展示）
- [ ] **最小授权**：按岗位配权，定期回收；离职即时收回
- [ ] **操作留痕**：谁、何时、看了/导出了哪些数据，日志不可篡改
- [ ] **导出管控**：批量导出需审批、加水印、限额
- [ ] **委托处理**：与第三方（云服务商/外包/客服系统）签订数据处理协议
- [ ] **删除机制**：到期删除或匿名化，并有执行记录
- [ ] **泄露处置预案**：发现 → 遏制 → 评估影响范围 → 按法定路径报告 → 通知受影响个人

### 2.5 常见误区（**最忌这里出错**）
- ❌ 「我们没收集身份证，所以不用管」——**任何可识别到个人的信息都算**，含 IP、设备号、Cookie 标识、行为轨迹。
- ❌ 「数据存在境外云上但我们没主动传」——**使用境外服务本身就是传输行为**，需先判定是否构成出境。
- ❌ 「签了隐私政策就等于有同意」——**默认勾选、捆绑同意、拒绝即不可用**均不构成有效同意。
- ❌ 「匿名化 = 假名化」——**假名化仍属个人信息**（可复原），只有匿名化（不可复原）才脱离个人信息范畴。
- ❌ 「出事删日志就行」——**销毁证据**本身可能构成独立的违法情形。
