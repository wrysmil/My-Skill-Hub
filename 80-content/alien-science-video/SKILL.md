# AI 外星人科普视频制作

用固定双主角把一个与观众有关的科学问题，拍成角色正在经历的科幻故事。中文协作；代码、资产 ID 保留英文。目标是提高共鸣、可理解性和观看动力，不保证爆款。

## 两步工作流

### 第一步：和用户共创选题

读取 [选题与证据](references/topic-and-evidence.md)。先利用上下文判断受众与兴趣；信息不足时每轮只问一个影响选题的关键问题，同时给具体候选，避免长问卷。

- 默认给 5–6 张选题卡，先用紧凑表格比较，只展开最推荐的两张；用户只想轻聊时可先给三个方向，后续再细化：生活场景、观众心声、核心问题、外星人视角、预期奇观、科学核验难点、自然讨论点、相对潜力判断及理由。
- 推荐前两名，解释取舍。区分“有传播潜力”和“已有传播数据”，不以自评分替代平台数据。
- 用户提出方向时围绕它细化，不强行另选。用户给出明确选题并要求制作，视为已选定，可直接进入第二步。
- **用户尚未选择时停在选题共创，不输出完整剧本、主体清单或分镜。** 提供的示例钩子不算用户确认。
- 用户明确授权“你选一个直接做”可代选并说明理由；“想做爆款”“推荐一下”不构成代选授权。

确认后的 TopicBrief 包含：episode_id、观众、生活触发、核心科学问题、一句可核验结论、情绪落点、叙事反转、事实来源、目标时长、画幅、制作工具。除科学结论外的缺省项直接用默认值并说明，不重复确认。

### 第二步：主体资产提取专家 → 分镜拆分专家

默认抖音竖屏 9:16，90 秒，约 12–16 镜，单镜 4–8 秒；用户指定优先。科普复杂度超出时长时删减到一个问题，或明确建议延长，不把长台词塞进短镜头。参考片的横屏不是本系列的强制画幅。

1. 主控先完成最小事实核验和 6–8 个故事节拍，再读取 [固定人物](references/character-bible.md)。参考图只有部分文字可见时，记录可读部分，不补写截图以外的内容。
2. **主体资产提取专家**：读取 [专家契约与输出](references/production-contracts.md) 的专家 A。输入 TopicBrief、故事节拍、角色圣经；输出 AssetPack（角色、场景、关键道具、机制可视化与参考图提示词）。固定角色复用，不每集重设计。
3. 主控检查 AssetPack 的资产 ID、事实比喻边界及一致性；补齐后交给下一专家。
4. **分镜拆分专家**：读取同一参考中的专家 B。输入 TopicBrief、故事节拍、角色圣经和已经核对的 AssetPack；输出 StoryboardPack，每镜资产引用、动作、台词、图像提示词、视频提示词及衔接明确。
5. 主控整合，检查时长、朗读容量、主体一致性、事实与视觉是否互相矛盾，交付制作包。

有原生子 Agent 能力且允许委派时，分别派发两位专家；**B 依赖 A，不可两人同时自由发挥后拼接**。同一目录并行时各自只写所负责的文件，不覆盖他人。无子 Agent 时，明确说明以两次角色化工作完成，不伪称已调用专家。专家返回不等于验收通过，主控负责整合。

## 系列的叙事与镜头语言

从用户参考图中可见的结构提炼，按主题调整，不机械凑段落：

**生活问题 → 外星人反直觉但有根据的回应 → 男主追问 → 进入可视化机制 → 尺度或认知升级 → 视觉高潮 → 返回生活，改变一个小动作。**

- 前 5 秒出现具体问题、异常画面或有生活根据的冲突。不要自我介绍、片头 logo、虚假危险或“科学家不敢说”。
- 男主是有正常推理能力的普通人，替观众提出质疑，不能为了衬托外星人而降智。
- 女性外星人温和、端庄、理性，有轻微幽默；让主角观察验证，不以高等文明身份压制异议。
- 一段台词配一个能解释它的动作；不要角色说完再无关炫技。宏观—微观变化必须推进理解。
- 比喻是解释工具：注明什么对应真实机制、什么只是剧情。视觉不能演出错误因果，再靠字幕补救。
- 尾声回扣开头，可留一个真实经历问题，不制造假争议、羞辱观众或索要机械评论。

## 交付与状态

第一步只交付候选及选择问题。第二步交付：

1. `episode-brief.md`：选题、事实依据、故事梗概、逐段节拍与台词。
2. `assets.md`：AssetPack，固定角色复用信息、主体和场景参考图提示词。
3. `storyboard.md`：完整逐镜表 + 每镜可单独复制的生图、生视频提示词。
4. `generation-plan.md`：资产生成与镜头生成顺序、联系表用途、配音与字幕建议、自检结果。

用户只要前几镜或部分资产时，按请求缩小交付：标明覆盖时间、已交付与待补项，不强制四份文件或全片镜头齐备。只验收本次范围；局部通过不等于全片完成。

科学证据不足时，可交付不依赖该结论的生活开场、角色与普通场景；把缺证据的机制镜和答案标为阻塞，列出需要核实的结论，不虚构机制、来源或成片闭环。

目录尊重用户工作区规范；无规范时用工作区 `video-projects/<episode_id>/`。只生成文本制作包，除非用户另行要求生成图片、视频或发布；不自动发付费请求、上传或发布。

角色圣经是已设计的文本资产，**不是已生成的参考图**。先生成并确认角色参考图，才标记为 visual_locked；没有图时标记 text_designed。上下文换轮时先读已有 Brief、角色版本及资产状态，不重复让用户选已确认的方向。

## 完成前自检

- 话题已选定；一个清楚问题、一条可核验主结论；结尾兑现开头。
- 主体 ID 与版本无漂移，分镜仅引用存在的资产；必要的状态变体列明。
- 时间轴连续，镜头总长等于目标时长；台词连同停顿留得下，详见专家契约。
- 每镜有可执行的单一主要动作与衔接；动态提示词包含运动过程，不是静态形容词堆砌。
- 健康、心理等内容的结论有可靠出处，故事装置与真实机制分清；没有承诺热度或捏造指标。
- 模型、画幅、字幕、联图与独立镜头用途相容；未实际生成的图片和视频如实标记。

本 Skill 的研究边界与来源见 [参考依据](references/research-basis.md)，只在用户追问来源或继续竞品研究时读取。
