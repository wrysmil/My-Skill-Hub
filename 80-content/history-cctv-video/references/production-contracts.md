# 资产与分镜契约

## AssetPack

给本集需要的主体和场所建ID，例如C01角色、A01动物、L01场景、P01道具、V01声音。无需使用不存在的资产类别；一个人物的衣服不用拆成多个角色。

每个资产记录：

| 字段 | 内容 |
|---|---|
| id 与 version | 本集稳定ID与当前版本 |
| type 与 name | 角色、动物、场景、道具或声音 |
| appearance_or_layout | 少数可见且有区分度的外观或布局锚点 |
| states | 剧本确有需要的状态，如门关闭/开启、衣服干/湿、站立/坐下 |
| references | 已有参考的路径、来源及用途；不存在就写“待生成” |
| image_prompt | 可独立复制的自然语言生图词；纯声音资产写voice_brief，不写伪造图像词 |
| status | text_designed、visual_checked、visual_locked；实际失败另外记录具体原因 |

### 角色和动物

按题材重新设计年龄感、体型、发式、服装、色彩和辨识锚点，不套影视演员面孔。单独生成清晰全身或三分之四视角，再视需要做侧背面，人物与动物正常解剖。故事需要多个外观相近角色时，用体型与服装差别增强可读性。

中性定妆图服务一致性，最终镜头图服务剧情构图；定妆图可清楚，成片可适度录像压缩，二者不必拥有完全相同噪点。

### 场景与机位

L01需包括门窗、通道、可行动区域、关键道具位置、光源方向。为每个机位登记：

- camera_id、所属L资产、位置与俯视方向、景别和画幅。
- 谁从画面哪边进入，出口在哪，主体之间谁左谁右。
- 可见区域与遮挡区域；与另一机位的关系。

监控感来自固定广角、高处视点、深景深、连续行动与适量后期录像处理。不是所有监控都必须冷灰、模糊、夜视或带同一CAM编号。画面中不必出现现代摄像头实体。

### 生图提示词结构

资产图：主体身份与少量外观锚点 → 姿态/视角 → 材质与光线 → 背景用途 → 必要约束。

镜头首帧：本镜所用主体的完整简述 → L场景及具体构图 → 动作开始前的姿态 → 光色/机位/画幅 → 必要约束。

人物/道具准确识别所必需的文字可以后期添加。监控角标、精确时间码、字幕统一交剪辑；不要让生成画面承担持续稳定排字。

## StoryboardPack

先交紧凑镜头表：

`shot_id | start_s | end_s | camera_id | asset_ids及状态 | 主要动作 | 对白/声音 | 如何接下一镜`

再为每一镜展开：

1. **输入参考**：已有图片路径与角色，或明确待生成的资产ID。ID是制作引用，不假定模型会自动理解C01。
2. **静态首帧提示词**：主体外观、场景布局、初始站位、机位、光色、画幅；每镜可以独立复制使用。
3. **动态视频提示词**：谁从哪个状态开始，先后发生什么，如何停下；机位固定或按用户指定变化。
4. **末帧状态**：人物/动物/道具位置、门开合、姿态、视线方向。
5. **声音与后期**：对白、环境声、拟音及准确字幕；区分建议声音与已经生成音轨。
6. **验收与降难**：本镜最可能失败的动作点；失败时缩减动作或拆成起势与结果。

每镜无需重复整份资产圣经，但可复制提示词必须包含该镜需要的具体外观和场景信息，不能只有“C01在L01行动”或“同上一镜”。有真实上传引用功能时，可用界面提供的准确素材标签代替长外观复述，并注明引用对应关系。

### 时间与连续性

start_s从0开始，上一镜end_s等于下一镜start_s，最后等于目标总时长。镜头数随剧本决定。生成素材可留少量剪辑余量，区分“请求生成时长”和“成片取用时长”，不能把带余量的总长当最终片长。

首帧是动作前状态：若动态词为“拾起地上的道具”，首帧不能已经握在手里。移动的门、手、关键道具要解释去向。动作省略允许剪辑，但不能把瞬移写成已验证连贯。

同机位接续优先提取前镜合格尾帧；画面结构错误则先修，不把畸形带进后续。文字分镜的空间一致只代表设计一致，视觉生成后还需查看验证。

### 声音

监控形式可采用环境声、画外音或少量对白，并非必须无声。有意增加配乐可作为创作变体。多人对白、远距离人物和长台词增加口型难度，可用可信的画外安排或后期配音，但不要让不出镜角色变成未登记的叙事捷径。

### 资产实际出图的最小闭环

按依赖顺序：角色/动物/道具参考 → 场景和机位参考 → 各镜独立首帧。沿用环境可用工具，不规定某一个厂商才能完成。用户只要求角色图时只生成角色图，不自动连生所有场景和视频。

生成后读取工具实际返回的路径并查看图像，比较身份、比例、必要道具和构图。失败只重做相关资产，保留已合格项；重大设计变化先更新版本再重做依赖镜头。检验通过与用户定稿不同，状态分别标记。
