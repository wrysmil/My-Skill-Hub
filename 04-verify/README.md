# ✅ 04-verify — 验证价值，让数据替你下结论

> **要回答的问题：有什么证据能证明它真的有用？什么情况下我该承认它没用？**

## 什么时候进入

- 当产品已经上线、有真实用户在用，你需要看数据决定继续、转向还是停的时候。
- 当有人拿注册量、下载量、访问量当成绩向你汇报的时候。
- 当你遇到任何 bug、测试失败或异常行为，在提出修复方案之前。
- 当你完成了一个大功能或准备合并代码，需要别人帮你把关的时候。
- 当你要从需求文档 / API 文档生成结构化测试用例，或要审查界面的可访问性与规范合规的时候。

## 什么时候不该进入

- 还没有真实用户行为数据 —— 只有你自己和朋友的试用构不成验证，此时该做的是拉用户，不是分析数据。
- 代码还没跑通、还没上线 —— 先回 `03-build` 把闭环做完。

## 产出物

- 一份在实验开始前就写下判据的验证实验记录：看什么指标、达到多少算成功、多少算失败。
- 一条留存曲线（或对应的激活 / 复购曲线），带时间轴和对照。
- 一份明确的继续 / 转向 / 停止结论，附上支撑它的原始数字。
- 一份测试用例表或代码审查记录，标明发现的问题与处理结果。

## 常见反模式

**「早期数据还不错」** → 早期用户是最宽容的一批人，他们留下来恰恰说明不了后面来的人会留下。

**「用户提了 12 条建议说明有需求」** → 提建议的成本是零，愿意付钱或愿意改变现有工作流才是需求信号。

**「平均值算出来就代表整体」** → 平均值会把"一小撮人重度使用"和"所有人都用了一次"压成同一个数字，要看分布。

**「数据不好是因为还没做推广」** → 这是把验证失败解释成执行不足，推广只会让更多人确认它没用。
