# 价值验证

## 这个技能解决什么

**核心原则：没有预先写下的判据，任何数据都能被解读成好消息。** 数据不会自己说话 —— 你怎么切它、跟什么比、取谁的均值，决定了它支持哪个结论。

上线之后真正的危险不是数据差，而是**数据差但你把它读成了"早期正常"**，然后带着这个判断又投入三个月。

## 触发条件

- 产品已上线，有了一批用户和起码一轮行为数据
- 要回答「继续投 / 转向 / 停掉」
- 有人用累计注册量、日活数、平均使用次数来描述成绩
- 要设计一个验证实验（含付费测试）
- 准备拿数据去融资、汇报或说服别人

## 不适用

- 还没有任何真实用户 —— 那是 `01-discover/pain-point-discovery` 的阶段
- 数据量小到无法构成任何比较（非熟人用户 < 5）—— 先去拿用户，不是先分析

## 第一步：把指标分成三类

| 类型 | 特征 | 例子 | 用途 |
| --- | --- | --- | --- |
| 虚荣指标 | 只增不减，与产品价值无关 | 累计注册、累计下载、总访问量 | **只能用来对外讲故事，不能用来做决定** |
| 可行动指标 | 变了你知道该改哪里 | 注册→首次完成核心任务的转化率、某一步的流失率 | 指导产品改动 |
| 判据指标 | 事先定好线，过/不过 | 次周留存、非熟人用户数、付费人数 | 决定继续还是停 |

**决定去留只能看第三类。** 前两类出现时，先问一句：这个数字变了，我会做不同的决定吗？如果不会，它就不该出现在决策页上。

## 第二步：拆掉平均值

平均值是早期数据里最危险的东西，因为它会把极端分布抹平成一个"看起来还行"的数。

> 例：日活 5、注册 100、平均每周打开 1.2 次。
> 这个 1.2 很可能是「3 个人每天打开 + 97 个人打开 0 次」平均出来的。
> **你手上其实只有 3 个数据点，不是 100 个。**

拿到任何平均值，先做三件事：

1. **拆分布**：把用户按使用频次分桶（0 次 / 1 次 / 每周几次 / 每天），看每一桶有多少人
2. **算分母**：这个百分比的分母是"注册用户"还是"激活用户"？分母选错，结论一定错
3. **看中位数和极值**：重度用户是谁？他们和流失用户有什么结构性差别？

## 第三步：只看留存曲线，不看留存数字

**单点留存率没有意义，曲线的形状才有意义。**

```
好：D1 40% → D7 20% → D14 18% → D30 16%   ← 在非零水平上"变平"
坏：D1 40% → D7 15% → D14 4%  → D30 0%    ← 一路归零
```

- **变平**的那条水平线的高度，就是你的 PMF 上限，也是你该拿去做增长的地基
- **一路归零**说明用户来过一次就再没有理由回来 —— 这时候加功能、投广告都是浪费
- 曲线还没变平时谈融资＝拿一个无法辩护的故事去换钱

**必须先排除的一件事：留存是"产品留存"还是"人情留存"。**

如果那 3 个每日用户是你从私人关系里拉来的（朋友、前同事、群里熟人），他们每天用是社交义务，不是产品价值。**这一条没验证之前，其余分析全部空转。**

判断方式（逐条问）：
- 「你用之前是怎么解决这个问题的？现在还在用那个方法吗？」
- 「如果明天这个产品关了，你会怎么办？」→「那就换回 XX 呗」= 可替代；「那就麻烦了 / 我得回去用 Excel」= 有价值
- 「10 分制，你有多需要它？」→ 7 分以下不算需求成立

## 第四步：把用户建议分成信号和噪音

用户提了 12 条建议 ≠ 有 12 个需求。提建议的成本为零。

| 建议类型 | 判读 | 怎么处理 |
| --- | --- | --- |
| 「让我更快完成核心任务」 | **信号** | 优先做 |
| 「加一个 XX 功能」 | 噪音 | 先问：他是在完成核心任务时卡住了吗？ |
| 「能不能支持 XX 格式 / 平台」 | 看频次 | 3 个以上独立用户提 = 信号；1 个人提 = 噪音 |
| 「能不能免费 / 便宜点」 | 等价于「价值不够」 | 不是定价问题，别急着打折 |

**纪律：不要按建议排期。** 3 个用户提 12 条建议，只证明这 3 个人话多。

## 第五步：预注册判据（在实验开始前写）

```markdown
## 验证实验：<名称>        预注册日期：____

样本定义：非熟人用户，来源渠道 ____，样本量 ____
观察窗口：____ 周

| 判据指标 | 口径（分子/分母/时间窗） | 继续 | 转向 | 停 |
|---|---|---|---|---|
| 非熟人用户次周留存 | | ≥ __% | __–__% | < __% |
| 非熟人用户 4 周留存 | | ≥ __% | __–__% | < __% |
| 每日/每周主动使用人数 | | ≥ __ 人 | | |
| 付费人数（真实付款） | | ≥ __ 人 | | 0 人 |
| 完整体验核心任务的用户占比 | | ≥ __% | | |

结论约定：判据指标中任意 __ 项落入「停」区间 → 停止或转向。
```

**预注册的判据不能事后修改。** 改了要新开一版，并把旧版留在文件里 —— 那是你判断力的证据。

## 三档结论怎么下

| 结论 | 条件 | 动作 |
| --- | --- | --- |
| **继续投入** | 非熟人用户留存曲线开始变平，且至少有 1 人真实付费 | 进入增长实验，可以开始搭融资叙事 |
| **转向** | 有一定留存（非零），但无人愿意付费 | 通常换人群或换场景，**不是换想法**；重跑一轮 |
| **停掉** | 日常用户验真后全是熟人，且冷启动新用户 4 周留存趋零；或连续两轮实验留存均归零 | 停。及时停是这套流程最省钱的能力 |

**转向不是失败，是这个流程最有价值的部分。** 绝大多数项目死在没有勇气转向。

## Red Flags — 出现这些想法就停下

- 「早期数据还不错」→ 具体是哪个判据指标过了线？说不出就是没有
- 「累计注册 100 人」→ 虚荣指标，与产品价值无关
- 「用户提了 12 条建议说明有需求」→ 提建议成本为零
- 「平均每周打开 1.2 次」→ 平均数掩盖了极端分布，先拆桶
- 「数据不好是因为还没做推广」→ 推广解决的是"没人知道"，不解决"知道了不用"
- 「那 3 个用户每天必用」→ 先确认他们是不是你的朋友
- 「先做一版融资 PPT」→ 投资人第一个问题就是"付费为什么是 0、留存曲线在哪"，答不上来会被打上"数据不行还急着融"的标签

**出现任一条：回到预注册判据，用数字对一遍。**

## 常见错误

| 错误 | 修正 |
| --- | --- |
| 判据在看完数据之后定 | 判据必须**先写**，写在实验之前 |
| 用留存率单点下结论 | 画曲线，看是否变平 |
| 分母混用注册用户与激活用户 | 每个指标写清口径，写到别人能复现 |
| 把熟人样本计入留存 | 单独统计熟人 / 非熟人两套数 |
| 把「0 付费」解释为「太早」 | 两周 0 付费可以接受，但要立刻设计一次真实收费动作 |
| 按用户建议排优先级 | 建议按"是否指向核心任务"分类后再决定 |
| 一次实验想验证三件事 | 一个实验一个判据，否则出了问题不知道改哪个 |
