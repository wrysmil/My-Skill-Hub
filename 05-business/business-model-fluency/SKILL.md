# 商业模式与业务理解

## 这个技能解决什么

**核心原则：判断一门生意不看"市场规模有多大"，看"钱从谁的口袋流向谁的口袋、中间每一段剩多少"。**

技术人进入一个陌生行业时最常见的错误，是用"我能写出这个东西"替代"有人会为这个东西付钱"。市场规模报告（TAM/SAM/SOM）是最容易被滥用的数字 —— 它通常把"所有潜在相关的人"都算进去，而真实天花板是**你现在能触达并说服的人**。

这个技能的产出不是一份 PPT，是**一张钱流图 + 五个数字 + 一个明确的去做/不做判断**。

## 触发条件

- 准备进入一个不熟悉的行业或垂直领域
- 要评估一个方向值不值得投入（尤其在被"市场很大"说服时）
- 需要在一周内摸清某行业的商业逻辑
- 要设计定价、渠道，或判断能不能养活自己/团队
- 融资、汇报、写 BP 前需要把数字对齐

## 不适用

- 需求本身还没验证（先做 `01-discover/pain-point-discovery`）
- 商业模式已由现有合同或既有业务锁定

## 一周速通法

不要从"行业报告"开始，从"钱"开始。

| 天 | 动作 | 产出 |
| --- | --- | --- |
| D1 | 画产业链钱流图：列出从最终付费者到你的位置之间每一环，标出每环收谁的钱、抽多少 | 一张钱流图 |
| D2 | 列出 3 个直接竞品 + 2 个"用户其实在用的笨办法"（Excel、外包、纸质、熟人帮忙） | 竞品与替代方案清单 |
| D3 | 找 3 个从业者做三维访谈（见下） | 3 份访谈记录 |
| D4 | 影子跟单：全程旁观一个真实用户完成一次完整任务 | 一份流程时间轴，标出最烦的 3 个点 |
| D5 | 算目标客户单位的收入 / 成本 / 利润，找出他在哪一项最痛 | 一张客户单位经济表 |
| D6 | 填五个数字表（见下），做愿付价格锚定测试 | 五个数字 + 价格区间 |
| D7 | 算天花板，写下 Go / Pivot / No-Go 判断与依据 | 一页结论 |

**关键纪律：D3–D5 必须接触真实的人，不能只查资料。** 行业报告描述的是行业平均值，而你的客户不是平均值。

## 工具一：产业链钱流图

画出来你就知道自己在哪一环、上一环为什么愿意给你钱。

```
最终付费者（谁最后掏钱？）
   ↓ 为什么付？付多少？
渠道 / 平台（抽成多少？他们为什么分给你？）
   ↓
服务方（你的直接客户或对手）
   ↓
你在这里 —— 你替代了谁？还是新增了一环？
```

必答的三个问题：

1. **最终掏钱的人和实际使用的人是不是同一个人？** 不是的话，你的产品要同时讨好两个角色（企业软件里这是最常见的坑）
2. **你现在要进的那一环，利润率是被谁压住的？** 上游压还是下游压？
3. **你替代的是"预算"还是"零预算"？** 替代已有预算（他本来就在为这件事花钱）远比从零创造一个预算容易

## 工具二：三维访谈

对每个从业者问三层，缺一层结论就不成立：

| 维度 | 问什么 | 你在验证 |
| --- | --- | --- |
| 流程 | 你这周实际做了哪些事？哪一步最花时间？ | 真实工作流，不是他以为的流程 |
| 钱 | 这一块一年花多少钱？谁批的？怎么走流程？ | 预算规模与决策链 |
| 决策 | 上一家供应商你怎么选的？为什么换掉/没换？ | 采购标准与转换成本 |

**最有价值的一句问话：「如果有个工具能解决 XX，你会在什么情况下不买？」**

## 工具三：影子跟单

比访谈可靠得多。**全程旁观**一个真实用户完成一次完整任务，不要指导、不要打断、不要帮忙。

记录三样：
- 每一步实际花了多少时间（他会低估 3–5 倍，所以要实测）
- 他在哪里停下、叹气、切窗口、翻聊天记录
- 他用了多少种工具才拼出结果（**工具数量 = 痛点强度**）

## 工具四：JTBD（用户雇这个产品来干什么活）

不要问"你需要什么功能"，问：

> 「你上次遇到这个问题时，最后是用什么办法解决的？你当时其实想要的是什么结果？」

把答案写成一句 JTBD：**「当我 ____ 的时候，我想要 ____，这样我就能 ____。」**

- 一个产品只能服务 1–2 个 JTBD
- 如果你写不出这句话，说明你还在描述功能，没找到活儿

## 五个数字（不填完不许下结论）

任何人问你商业模式，这五个数就是全部答案：

| 数字 | 定义 | 及格线 / 说明 |
| --- | --- | --- |
| 客单价 ARPU | 每个客户每月/每年付你多少钱 | 必须区分"标价"和"实收" |
| 获客成本 CAC | 拿到一个付费客户的总花费 ÷ 付费客户数 | 含人力、广告、渠道分成，别只算广告费 |
| 客户终身价值 LTV | 客单价 × 毛利率 × 平均生命周期（月） | 毛利率必须扣掉服务器/第三方/交付成本 |
| 毛利率 | (收入 − 直接成本) ÷ 收入 | 软件通常 70%+；低于 40% 要非常警惕 |
| 回本周期 | CAC ÷ (月客单价 × 毛利率) | **≤ 12 个月**；> 18 个月基本靠融资续命 |

**一条硬线：LTV / CAC ≥ 3。** 低于 3 意味着每花一块钱只赚回不到三块，扣除团队和固定成本后是亏的。

## 天花板怎么算

不要引用 TAM。用自己的漏斗算：

```
真实天花板（年收入）
 = 你能有效触达的客户数
 × 现实渗透率（通常 1%–5%，不是 30%）
 × ARPU
```

**算完做一次诚实检查：** 这个数字能不能支撑你想要的生活/团队规模？如果 100 万 × 3% × 500 元 = 1500 万营收，而行业毛利率 30%，那就是 450 万毛利 —— 换算成几人团队、够不够？

**如果算出来撑不起你想做的事，这个数字比任何行业报告都重要。**

## 愿付价格锚定

不要问「你愿意付多少钱」（答案永远是"看情况"）。用三档逼选择：

```
方案 A：199 元/年 —— 基础功能
方案 B：499 元/年 —— 含 XX 与 YY
方案 C：999 元/年 —— 含全部 + 人工支持

「这三个里你会选哪个？为什么不是上一个？」
```

看出三件事：①他的选择落在哪一档；②他拿哪个方案和什么在比（这是你的真竞品）；③说到哪一档他开始说"太贵了"（那是价值感知的断层，不是价格）。

**最后一定要做一次真实收费动作** —— 哪怕只收 1 元、9.9 元。**真实付款是唯一能被信任的付费信号。**

## Go / Pivot / No-Go

| 判断 | 条件 |
| --- | --- |
| **Go** | 五个数字里 LTV/CAC ≥ 3、回本 ≤ 12 个月；天花板足以支撑目标；至少有 3 个非熟人真实付款；已识别出可重复的获客渠道 |
| **Pivot** | 需求真实存在（有人付钱或强烈痛），但人群/场景/渠道之一错了。**换一个变量重跑，不要换行业** |
| **No-Go** | 最终付费者与使用者分离且决策链超出你的触达能力；替代的是"零预算"；天花板算完撑不起最小目标；LTV/CAC 结构性 < 1（越卖越亏） |

**Pivot 的常见误区：同时换人群和产品。** 一次只换一个变量，否则你不知道是哪个起了作用。

## Red Flags — 出现这些想法就停下

- 「市场有 1000 亿，我们只要 1% 就够了」→ 1% 是最典型的自我安慰；用自己的漏斗算
- 「这个行业的人都用 Excel，机会巨大」→ 用 Excel 可能是**没有预算**，不一定是没工具
- 「先做起来再说，商业模式以后再想」→ 商业模式的三个数决定产品形态，不是反过来
- 「我们暂时不赚钱，先做规模」→ 规模只在你获客成本递减时才有价值，否则是加速亏损
- 「客户说很喜欢，就是预算还没批」→ 等预算 = 没预算，先确认有没有替代预算科目
- 「技术领先就是壁垒」→ 技术壁垒的半衰期通常短于销售周期；真正的壁垒是渠道、数据积累、切换成本、合规资质
- 「竞品做得烂，我们做好就行」→ 做得烂还能活着，说明它握着你没有的东西（渠道、牌照、客户关系）
- 「我先把产品做出来，再去跟行业内人聊」→ 顺序反了，先聊，聊完再决定做什么

**出现任一条：回到五个数字表，用数字对齐。**

## 常见错误

| 错误 | 修正 |
| --- | --- |
| 用 TAM/SAM/SOM 代替自算天花板 | 用自己的触达数 × 现实渗透率 × ARPU |
| CAC 只算广告费 | 含人力、渠道分成、销售周期成本 |
| LTV 用收入算不用毛利算 | LTV = ARPU × 毛利率 × 生命周期 |
| 把"标价"当"实收" | 折扣、赠送、免费额度都要扣掉 |
| 一次 pivot 换多个变量 | 一次只换人群/场景/渠道之一 |
| 调研只查资料不见人 | D3–D5 必须接触真实从业者 |
| 相信客户自报的时间 | 影子跟单实测，通常差 3–5 倍 |
| 把"技术领先"当护城河 | 列出渠道/数据/切换成本/资质，逐项验证 |
