# 🧰 00-meta — 让 Agent 更好用的基础设施，贯穿全程但不占流程位置

> **要回答的问题：我该怎么把重复的做法变成能力，而不是每次重新解释？**

## 什么时候进入

- 当你在同一个项目里第三次向下手解释同一套约定（目录结构、命名、提交规范）的时候。
- 当你想把自己摸索出来的一套做法固化下来，让它在别的项目里也能复用的时候。
- 当你要判断某个能力是否已经有现成技能，纠结"用别人的还是自己造"的时候。
- 当你自研的 DSH 插件已经能跑，需要发布到插件市场的时候。
- 当工作跨了多个会话、上下文快被撑爆，或者你需要 Agent 记住项目约定的时候。

## 什么时候不该进入

- 你还没有任何重复过的做法 —— 没有重复就没有模式，此时造技能只是把一次性操作提前封装，纯属浪费。
- 你正卡在具体的业务推进上（需求没验证、MVP 没做出来）—— 元能力是效率工具，不是进度替代品。

## 产出物

- 一个可复用的 `SKILL.md`，含 `name` / `description` 元数据与可执行的工作流章节。
- 一份项目记忆文件，记录跨会话必须保留的约定与决策。
- 一份技能检索结论：找到候选技能并给出复用或自研的明确判断。
- 一个已发布的 DSH 插件包及其版本元数据，可在插件市场被安装。

## 技能

| 技能 | 什么时候用它 |
| --- | --- |
| [`skill-creator`](skill-creator/) | 你已经有一套稳定的做法想固化成可复用技能，或要迭代、评测已有技能时 |
| [`find-skills`](find-skills/) | 你不确定某个能力是否已有现成技能、要不要自己造的时候 |
| [`dsh-plugin-publish`](dsh-plugin-publish/) | 自研 DSH 插件要发布到插件市场、需要刷 CDN 更新版本时 |
| [`memory-bank`](memory-bank/) | 跨会话工作、上下文快被撑爆、需要让 Agent 记住项目约定时 |

## 常见反模式

**「这些约定我记在脑子里就行，不用写下来」** → 换个会话、换个 Agent，你的脑子里没有任何东西能被读到，前面解释过的全部重来。

**「市面上肯定没有，我直接自己写一个」** → 先去 `find-skills` 检索一遍，重复造技能的成本远高于复用。

**「技能先写长一点，把所有细节都塞进 SKILL.md」** → 正文越长每次加载吃的上下文越多，深度内容应该拆到 `references/` 按需加载。

**「项目记忆就是聊天记录，Agent 自己会记住」** → 会话结束上下文就没了，没落成文件的约定等于不存在。

## 下一步

元能力不按阶段推进：它随时可以被调用，用完立刻回到你当前所在的主线阶段。如果你发现自己正在反复解释同一件事，说明现在就是该回到 00-meta 把能力固化下来的时机。
